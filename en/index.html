    Product

    Stories where content is data

    The player reads a story and picks lines and actions. Choices change relationships with the characters and the scenes that follow. New chapters are meant to ship regularly, so stories live on the server and the app only plays them back.

    • Scene

      A background, up to three characters, a line of dialogue and choices. The heroine slides in from the left when she speaks or thinks.

    • Branching and memory

      Ink variables: relationships, flags, the heroine's character. Decisions carry over between chapters.

    • Paid choices

      Special lines and scenes cost gems. The server sets the price, not the client.

    • Chapter tickets

      Up to two, plus one every two hours. Without a ticket, the player watches a rewarded ad or pays with gems.

    • The player's hero

      Name and appearance at the start of a story, plus a wardrobe with purchasable outfits along the plot.

    • Saves

      Resume from any line. A copy lives on the server, so progress follows the player to another device.

    • Catalog

      Genre shelves, “Continue”, and “New” and “New chapter” badges.

    • Online only

      The wallet and purchases live on the server. Without a connection, the game shows a reconnect screen.

    Engine

    A custom Ink runtime with a genre layer on top

    • Ink runtime ported to Dart

      inkjs 2.4.0, rewritten from TypeScript into pure Dart. The API mirrors the official one: continueStory, currentChoices, variablesState, state as JSON. Where inkjs diverges from the original C# runtime (integers vs floats, truthiness), the port follows C#. All 224 ported inkjs tests pass.

    • Scene commands as text lines

      The writer stages backgrounds, characters and music with lines like @bg, @show and @music. Ink external functions don't work for this: the runtime calls them while looking ahead, so a command would fire before its line is shown.

    • story_engine: Ink stream → events

      Line, command, choices, variable change, end. The engine keeps SceneState (what's on screen right now) and a snapshot for saving. The player subscribes to events and knows nothing about Ink.

    • Saves survive edits

      Every chapter has a fingerprint of its structure without the text (FNV-1a 64). Text in a released chapter can still be edited. If the structure changes, the chapter restarts from a checkpoint and purchases are kept.

    • Paid chapters aren't in the app

      The build tool moves their knots to the server. The client fetches a chapter after purchase and splices it into the story, so it can't be pulled out of the binary.

    Flutter client and scene player

    Riverpod 3 for state and dependencies, go_router for navigation. Environments are JSON configs: the server, store, ads and product IDs are chosen at build time. An incomplete config falls back to test stubs and logs the problem instead of crashing.

    • Live backgrounds

      A video loop over a still image via video_player. On the web and with the system “reduce motion” setting, only the still is shown.

    • Layered characters

      Body, outfit and emotion face on a 1200×2400 canvas. The speaker is highlighted and the others are dimmed.

    • Typewriter text

      22 ms per character, and a tap completes the line. An invisible tail keeps the box height steady, so the text doesn't jump.

    • Pause menu

      Reading log (last 200 entries), relationships with characters, settings.

    • Screens

      Catalog, story page, hero creation, wardrobe, shop, account, legal documents and consent.

    • Audio

      Scene music and sound effects through an AudioService that respects the player's settings.

    • Notifications

      Local ones for tickets, reminders after 1 and 3 days, and quiet hours. Push for new chapters.

    • Analytics

      Funnel events in AppMetrica after the player consents. Revenue is logged once the server grants the purchase.

    Server

    The server owns money and progress

    Supabase: Postgres, Storage and Edge Functions. The client can't change a balance directly. It calls a function that checks the price, locks the wallet row and records the operation in a ledger.

    • Idempotent purchases

      Every charge goes through a key like interference:choice:ch1_elias_private. A repeated request never charges twice.

    • Server-side prices

      The price list is tied to a story version. If the client sends an outdated price, the server answers price_changed.

    • Store purchases

      The purchase Edge Function verifies payment and grants it once per transaction. The store transaction is finished only after the grant, and anything paid but not granted is delivered at the next launch.

    • Sign-in and profile

      Players start as guests with an anonymous profile, then link VK ID or Yandex ID (through a custom OAuth bridge), Google or Apple. Account deletion is built in, as the stores require.

    • Content publishing

      Files are stored in Storage under their content hash, and unchanged files are never re-uploaded. Drafts are visible only to testers. A release is a single command that also sends a new-chapter push.

    Art and neural networks

    Neural networks draw, in-house tools make it game-ready

    There's no artist on the team. Neural networks generate the characters and locations. In-house tools handle cut-outs, a shared canvas, emotions that keep the same face, live backgrounds and audio, and story_cli art rebuilds only what changed.

    1. Midjourney

      One approved frame per character: pose, outfit, lighting. Backgrounds and the cover are generated the same way.

    2. Nano Banana Google Gemini

      Emotions from a head crop: only the brows, eyelids, eyes and mouth change. The face, hair and lighting stay the same.

    3. BiRefNet

      The background is removed locally and semi-transparent edge colors are cleaned, so dark scenes show no halo. The figure is placed on the canvas by template, with the top of the head at 5% from the top.

    4. In game

      Faces are pasted back into the frame and layers are assembled in the scene. Five characters, with three to six emotions each.

    Live backgrounds

    Custom Python VFX instead of video generation

    A still frame is brought to life procedurally with NumPy and OpenCV. Only the named elements move and everything else stays put, so the frame doesn't drift the way generated video does. A scene is a small file listing effects and coordinates. The loop is closed: the last frame matches the first, and the seam is checked automatically.
